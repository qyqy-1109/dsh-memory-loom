# yu（余）

给 **DeepSeek Harness** 用的跨会话**记忆 + 人格**层：记忆有分层与写路径治理，人格有内核、原理账本与取舍账本。

> 名字是 **yu（余）**。*余* = 压缩之后剩下的那部分，也就是这套东西的核心判断：
> **成长靠压缩不靠累积，剩下的那部分才是你。**

> English: [README.en.md](README.en.md)（面板文案 zh/en 双语，记忆内容保持你写的原文）

> 安装身份：`@qyqy-1109/yu`（0.56.0 起正式改名；作用域名先在临时 profile 里验过才动）。
> 插件内部 id、HTTP 路由与数据目录**仍然沿用 `memory-loom`** —— 改名不搬库，
> `~/.dsh/memory-loom/store.json` 原样可用。

设计直接搬自「旧识（old-acquaintance）」那套记忆架构，但按 DSH 的宿主能力重新落地 ——
不是把 Python 服务搬过来，而是把**口径**搬过来：

| 旧识里的东西 | 这里的落地 |
|---|---|
| 四层记忆（原文 → 摘要 → 事实+向量 → 遗忘/作废） | 原文由 DSH 会话日志负责；`summaries` 留摘要把；`memories` 存事实短句；容量/衰减/归档实现「会忘记」 |
| 写路径治理（查重 ≥0.92、冲突软删归档、约束只解除不删、状态变化兜底） | `MemoryStore.write()` 一条治理链：查重 → 作废/解除 → 落库 → 容量淘汰 → 归档修剪 |
| 读路径（约束常驻 → 【我是谁】 → 槽位 → 共同经历 → 世界 top3 → 事实 top3 带时距/弱相关 → 摘要） | `agent/pre-step` 每轮第一步注入，块名与标注沿用原口径 |
| 共同经历 `episode` 独立不淘汰 | `kind=episode`，带 `scene` / `significance`，按重要度常驻注入，只受容量上限约束 |
| 状态槽位覆盖式更新 | `kind=slot`（entity × attr 唯一），全量注入，不参与淘汰 |
| 六层健康灯 `ok/empty/degraded/disabled/unknown` | 写入 / 摘要 / 召回 / 约束 / 槽位 / 共同经历 |
| `events` 只增埋点 | 面板「审计」页；写入/去重/作废/解除/淘汰/修剪都可数 |
| 人格（v0.51 起自加的一层） | `state.self`：内核（三观，**只有人能写**）+ 原理（每条挂证据账）+ 操作流水；每轮注入在 `【我是谁】` |

一个刻意的差异：**没有 embedding、零运行时依赖**。召回用「CJK 二元组 + ASCII 词」建倒排，
按 **IDF 加权的查询覆盖度**打分（`lib/rank.js`），阈值可配；中文提问还会经 `lib/aliases.js`
补一层领域别名（`搜索 → search`、`撤销 → restore`）。好处是离线可跑、可回归、不花一次 API 调用；
代价是近义改写不如向量。要换回向量召回，只需替换 `lib/store.js` 里算分的那一处。

## 安装

插件是**零运行时依赖**的本地包（不 import `@deepseek-ai/*`，也不联网构建）：

```sh
# 1) 拿到源码
git clone https://github.com/qyqy-1109/dsh-yu.git
cd dsh-yu

# 2) 装进某个 profile（desktop 是桌面版默认 profile）
dsh plugin --profile desktop add .

# 3) 重启 DSH（profile bundle 与 package manifest 变化需要重启，不是 HMR 范围）
```

装完在左侧导航栏会多出两项：「记忆海」和「人格」，和「插件」「自动化任务」同一列。

也可以直接给绝对路径：`dsh plugin --profile desktop add /path/to/dsh-memory-loom`。

## 三层防爆（v0.22.0）

1. **归纳（无损压缩）**：活跃条数到 `compactAt 1200` 时，把同主题的冗余条目归纳成一条摘要
   （`【归纳·主题】共 N 条：1. … 2. …`），原条目转归档（`reason: summarized` 并指回摘要 id），
   随时可追溯。摘要进入召回的【更早之前】块。
   - 起名用**成员间最长公共前缀**再按功能字/序号/量词截断（`渲染帧率在第` → `渲染帧率`）——
     不用"最高频 n-gram"，因为模板化文本里任何子串频次都一样，会选出"下需要自"这种跨词碎片。
   - 前缀给不出标签时的兜底（v0.30.2）：剔掉泛动词（`新增/修复/补齐/接入…`）、版本片段、以功能字
     开头结尾的碎片，同频次优先更长的记号；成员大多带版本号（changelog 簇）时直接叫「版本进展」。
     老库里已经存下的泛词主题（例如「归纳·新增」）在加载时按新规则重算一次，只动泛词/空词。
   - 成簇 key 剔除**域内饱和词**（覆盖 ≥ 语料 40% 且语料 ≥ 12 条）：整库都在讲"记忆"时，
     「记忆」当主题等于没主题；一簇都分不出来时退回不过滤，宁可标签差一点也不能停止归纳。
   - 成本控制：60 秒冷却 + 活跃数再涨 80 条才触发 + 单次最多看 800 条（`summarySampleLimit`）。
2. **提前压缩**：不再只在撑到 2000 时才动，1200 就开始归纳，留出缓冲。
3. **world 独立上限**：`maxWorld 240`。它豁免容量淘汰（世界设定不能因为"少用"被删），但不能无限长，
   超出后归档权重最低的（`reason: world-capacity`，`explicit` 仍豁免）。

> 归纳是**确定性抽取式**的，不调模型：宿主的 LLM 能力在各 provider 插件里（注入式 `call.stream`），
> 记忆插件没有稳定入口，硬接会带来超时与"摘要失败卡住写入"的问题。归纳目标是压缩冗余而非重写文风，
> 抽取关键点足够，而且可复现、可测试、零延迟。

## 模型归纳（可选）

压缩产出的摘要默认是**抽取式**（抽要点拼接）。装了宿主模型服务时，可以再让模型重写成通顺的一段话。

- 调用路径：`ctx.llm.prepareCall()` + `ctx.llm.stream()`（`@deepseek-ai/dsh-llm`，dsh-base 已挂载）；
- 路由：配置 `summaryProvider`/`summaryModel` 就固定用它；留空则从 `listProviders()/listModels()` 发现第一条；
- **绝不在写入路径调模型**：写入时先生成抽取式摘要（约 6.6ms），模型重写在后台队列里做，
  成功才把 `generator` 改成 `llm`，失败只记 `llmError` 并保留抽取式；
- 并发 1、队列上限 8、单次超时 12s（都可配），超时/异常一律降级；
- 设置页显示引擎现状（`模型归纳：provider · model` / `不可用（回落到抽取式）`），
  provider/model 可直接在设置页改，改动会重新发现路由。

> 为什么必须显式或可发现：`resolveRoute` 在没有显式 provider/model 时会回落到**当前请求的路由**，
> 而归纳是后台任务、不在请求里，没有路由可回落。

## 恢复（自动化的安全网）

摘要归纳是自动的，判断偶尔会错 —— 所以必须有回退路径：

| 入口 | 用法 |
|---|---|
| `memory_restore({ id })` | 恢复单条归档记忆（「这条不该被归到那组里」） |
| `memory_restore({ summaryId })` | 撤销整条摘要：恢复它覆盖的全部成员并删除该摘要 |
| 面板 · 摘要页 · 「撤销归纳」 | 同上，一键整组回退 |
| 面板 · 条目详情 · 「恢复」 | 单条恢复（归档条目详情页里） |
| `memory_self({ action: 'restore', id })` | 人格按流水回退到某一步之前（见「按流水回退」） |
| 面板 · 人格页 · 成长记录 | 每一步都能「回到这一步之前」，理由必填 |

恢复时会把 `updatedAt` 推到当前时刻并累加命中 —— 否则它带着旧权重，
下一次容量淘汰会立刻又把它挑中，等于没恢复。

## 容量与防爆策略

| 机制 | 参数 | 行为 |
|---|---|---|
| 查重 | `dedupeThreshold 0.72` | 同 kind 内相似度够高就只累加命中，不新增条目 |
| **极性/编号守卫** | — | 相似度够高**还不够**：有/无否定不同、编号不同，一律分开存（见下） |
| 活跃上限 | `maxActiveMemories 2000` | 超出后按 `weightOf` **升序**归档（久不用 + 少命中的先出局） |
| 淘汰豁免 | — | `constraint` / `slot` / `world` 与 `explicit` 条目**永不淘汰** |
| 归档上限 | `maxArchive 500` | 超出后物理删除最老归档，不可恢复 |
| 事件流 | `eventsKeep 5000` | 流水只留最近若干条 |
| 时间衰减 | `halfLifeDays 30` | 权重随 30 天半衰，越久不碰越轻，先被淘汰 |
| 文本上限 | `maxTextLength 400` | 超长文本截断，防止整段对话入库 |

> **一个必须记住的坑**：「用户喜欢深色主题」与「用户不喜欢深色主题」的 CJK 二元组相似度
> 高达 0.86，只按阈值查重会把否定句并进肯定句，**存下来的意思正好相反**。
> 同理「第 1 条结论」与「第 2 条结论」相似度 0.96。所以查重前要过 `isSameClaim`：
> 极性（有/无否定）或数字记号不同，就不算同一件事。这是压缩，但不能是**有损且错**的压缩。

## 写入是怎么发生的

| 通道 | 触发 | 落库内容 |
|---|---|---|
| 工具 | 模型调 `memory_write` | 单条（kind+text）或 **一次多条**（`entries` 数组，最多 20 条，各自可带 `supersedes`） |
| 显式原话 | 用户说「记住…/别忘了…/以后都…」 | 原话（不改写），自动判定 fact / constraint |
| 定稿口吻 | 「改成…/换回…/就要这个/定稿/不要用…」 | 短句才收；带「一点/再/试试/暂时」的临时微调**不记**；带替换口吻时自动找相似旧结论 `supersedes` |
| 状态槽位 | `kind=slot`（entity×attr 唯一） | 覆盖式写入，每轮全量注入（适合"当前形态/当前版本"这类事实） |
| 提醒 | 连续 6 轮无写入 | 在注入块末尾追加一句提醒（之后每 4 轮一次） |

> 一条教训：一次长设计会话改了十几版，却没人调用写入，整段决策都没落库。
> 所以除了"模型自觉"，还补了**定稿口吻捕获**与**静默提醒**两条防线。

## 召回是怎么算的（v0.30.4）

- **查询只用用户原话**：宿主每轮追加的运行时样例（工作目录 / 文件策略 / 时间戳 / 审批状态）
  不是插件注入，`isInjectedContext` 挡不住，会跟着用户消息进检索 —— 实测 `recall.last.query`
  里整段 runtime context 都在，于是每次召回都被「记忆 / 文件 / 路径 / 当前 / 目录」这些样板词带偏。
  现在 `stripHostBoilerplate()` 在取原话时就把这些行和 `<memory-loom>…</memory-loom>` 剥掉，
  全被剥干净时返回空串（空查询比拿样板词去检索诚实）。
- **追问要带上文**：只有「短于 12 字」或「开头就是指代（那/这/它/继续/上面…）」的消息，才把
  上一条用户消息的尾巴（120 字）并进查询 —— 否则「那这个呢」本身召回不到任何东西；
  长句不并，避免把查询稀释。
- **给基准日**：注入块里每条都写「记于 N 天前」，却没有「今天几号」——「三天前说的那个」只能靠猜。
  现在头部固定一行 `今天：2026-11-07（周五，本地时区）`。
- **同一把尺子**：事实、世界、摘要全部走 IDF 加权覆盖率（`lib/rank.js`）。摘要块原来用 Jaccard
  （`similarity`），是 v0.29.0 已经从检索里换掉的那把尺子 —— 同一份查询两块用两种口径，排序会互相打脸。
- **并列怎么破**：覆盖率相同 → 摘要优先（它是 N 条压出来的结论）→ 再看权重（反复被召回/确认的
  结论排在"刚写的过程记录"前面）→ 最后按时间。
- 代价：`buildRecall` 在真实库（36 条活跃）上 0.61ms，和改造前一致（语料按 revision 缓存，多算一次不吃亏）。

## 共激活关系（v0.42.0，只观测）

记忆之间的线有两种来源，语义完全不同：

| 线的颜色 | 来源 | 说的是 | 怎么变 |
|---|---|---|---|
| 冷蓝 | 同簇 + 共享关键词 | 「这两条**写得像**」 | 静态：分词这把尺子决定形状 |
| 青 | **同一轮被一起召回** | 「这两条**一起被想起来过**」 | 动态：由使用累积，没人需要就自己衰减 |

只有青色那层可能长出没人预先写过的结构 —— 冷蓝那层再密也只是把相似矩阵画成了线。

- **数据**：`state.edges = [{a, b, w, at}]`，端点 a < b。每轮 `coRecall(ids)` 把这一轮
  **检索命中且非弱相关**的 id 两两记一次共现（`w = w·半衰 + 1`）。
- **常驻块不参与配对**：约束 / 槽位 / 共同经历每轮无条件注入，和所有东西都"共现"。
  放进来图会塌成以约束为中心的星形 —— 那等于没有结构。这和检索把高频词从分母里剔掉是同一件事。
- **必须有三道闸**：每点度数上限（`edgeMaxDegree 12`）、全局条数上限（`edgeMaxEdges 6000`）、
  衰减到 `edgeMinWeight 0.25` 以下剪掉。不设度上限就会长出全连接图，
  **全连接图 = 熵最大 = 零结构** —— "连得越多越聪明"是错觉。
- **一轮最多前 8 条参与配对**（`edgeFanout`）：8 条 = 28 对，再多每轮都在灌噪声。
- **这一版不碰注入**：边只影响面板怎么画，不影响任何召回决策。先让关系看得见，
  用一段时间判断它是不是真的有意义，再决定要不要让它反过来影响行为。
- **`共鸣` 是三态的**：`开 / 只看 / 关`。这一层的边天生稀薄（真实库跑六轮才六条），
  混在两千条冷蓝线里根本看不出长没长出来 —— `只看` 会把相似度线整片藏起来，只留青线与金线。
- `coActivate: false` 可整层关掉（老库、或不想让 `store.json` 再多这一层）。

### 演练里已经看到的偏差

拿真实库副本跑了 10 个查询，长出 48 条边 / 23 个节点 / 密度 0.19 / 最大度 10。最强的枢纽是
「用户最终选定的记忆面板形态」—— 它跟三个查询都相关、每轮都被召回，于是跟**所有同轮命中**都连上了。

这是共激活的固有偏差：**被召回的次数**决定度数，而不是**关系的重要性**。
真正的解法是归一化（本轮预算 `1/(n-1)`，或 PMI `共现 / (n_a · n_b)`），惩罚高频条目 ——
和 IDF 惩罚高频词是同一个道理。这一版故意不做，先观测原始分布再决定要不要引入。

判读方式：`关系 N` 那个数字在长 = 网在形成；`密度`长期偏高（面板 `graph.density`）
说明已经稠密到没有结构了，该收紧 `edgeMaxDegree`。

## 读闸门＝注入预算（v0.43.0 起）

注入是**常量开销**：只要库非空、只要有块能凑出来，每轮都会灌。实测「今天先做什么」这种问题
也会带进去 5 块 1435 字符，而它对这个问题毫无帮助。

所以 `buildRecall` 先过一道闸门 —— **它不是开关，是预算**：

| 查询的内容词数 | 注入上限 |
|---|---|
| 0（继续 / 你好 / 现在几点了） | 0 条：库里没有可想起的东西 |
| 1（咖啡 / 面板） | **1 条**：单词查询是"指路牌"，往往恰好指向一条具体记忆 |
| ≥ 2 | 正常 topK（3 条） |

- 内容词 = 长度 ≥2、非问句填词（什么/怎么/记得…）、非时间词（今天/现在/刚才…）、
  非寒暄应答词（继续/谢谢/你好…）、库里确实存在、且不是饱和词。
- 预算是按世界/事实/摘要三块各自取的，不是三块加起来共用。
- 常驻块永远不受影响：约束和槽位不是"这一轮想起了什么"，是"任何时候都必须知道的"。
- `recallMinContentTokens`（默认 2）调"给足预算需要几个内容词"；设 0 整层关掉（老行为）。
- `buildRecall` 返回 `gate: {budget, tokens, need}`，面板能说出"这轮为什么只想起一条"。

### 为什么不用「相关度」当判据

用覆盖率试过，直接失败 —— 覆盖率的分母只有查询词，短查询撞上一个二元组就是满分：

| 查询 | 峰值覆盖率 |
|---|---|
| 继续 | **1.000** |
| 现在几点了 | **1.000** |
| 今天先做什么 | **1.000** |
| 渲染帧率和光效怎么调的 | 0.500 |

`现在几点了` 拿 1.0，是因为"点了"命中了「面板开关的教训……判为"没动静"」里那两个字。
无关查询比一半真相关查询分数还高 —— 这把尺子在短查询上是废的。

换成"命中的内容词个数"才分得开：12 条无关查询里 9 条内容词不足两条。

### 为什么不做「单个稀有词放行」

0.43.0 先做过一版："内容词不足 2 个，但那个词 df ≤ 2（稀有）就放行"。
实测直接失效：**80 条的库里 df ≤ 2 的词一大片**，任何两字短语第一次出现都是 df=1，
"稀有"等于没说，闸门又退回到只在 0 个内容词时生效。

拿绝对计数当阈值，库一小就全部命中。丢掉这个概念、换成预算之后，"咖啡要能想起来"
和"随便发一句别灌满"两件事同时满足，而且规则只有一条。

### 实测效果（真实库，24 条查询）

| | 改进前 | 改进后 |
|---|---|---|
| 无关组平均注入 | 1206 字符 | **1115 字符**（12 条里 7 条零检索块） |
| 相关组平均注入 | 1610 字符 | 1598 字符（零误伤） |

## 使用信号：被用上，而不是被展示（v0.44.0，只记不改）

`hits` 记的是"被召回"，而被召回几乎每轮都会发生 —— 它度量的是**曝光**，不是有用。
后果是回声室：被召回的条目权重更高、于是更容易被召回，与"重不重要"无关
（真实库体检：42% 的条目从未被召回，命中前 10 条占了一半）。

`used` 是另一把尺子：给每条记忆取几个**指纹词**（IDF 最高的 3 个），
**下一轮你说话时**如果出现了指纹词，才算"用上了"。

- 判定滞后一轮：`decision.messages` 只含本轮（实测过），拿不到上一轮的答案。
- 一份注入可以在接下来 3 轮里被验收：记忆常常是"过两轮才被用上"。
- 只比对**你**的消息，不比对模型的回答 —— 否则"我说过什么"会反过来证明"这条记忆有用"。
- 门槛是命中 **1** 个指纹词：指纹词本身就是 df 极小的词，命中一个已经很强。
  实测要求 2 个时，7 条明显在说同一件事的消息只有 1 条判得上。
- 指纹词会切出「冲咖」「层记」这种跨词碎片（中文无分词器）。那是**安全的失败方向**：
  碎片只会更难命中（漏判），不会把无关的话算成"用上了"（误判）。

**这一版只记不改**：不动 `weightOf`，淘汰顺序和以前完全一样。先攒数据，
看 `used` 的分布能不能真的把"有用的"和"只是被展示过的"分开，再决定要不要让它进权重公式。

### 怎么读这个数字（v0.45.0 起）

面板顶部有 `用上 N`，「召回」页签里还有本轮的 `注入 N 字 / N 块 / N 条` 和闸门的人话解释。

**`用上 ÷ 召回` 才是这套系统第一个真正的健康度指标** —— 在这之前唯一的指标是"条数"，
而条数什么也说明不了。

要算这个比值，光有分子不够，还需要分母：

| 埋点 | 回答什么 |
|---|---|
| `recall`（每轮一条，只记体积不记正文） | 一共注入了多少次、每次多大 |
| `memory.usage`（一份注入结案时一条） | 给了几条、命中几条、第几轮结案 |
| `memory.used`（命中时一条） | 哪几条真被用上了 |

> 上线一天后的体检：`usedTotal = 0` 而 `hits = 102`。原因不是信号坏了，而是**看不到分母** ——
> 既没有每轮的注入记录，也没有未命中的痕迹，"used 到底有没有机会触发"根本无从判断。
> 所以先补观测，再谈淘汰。**顺序不能反。**

### 复核：这个口径没成，换成「被改写」

分母补上以后，读数直接判了这个指标死刑：

```text
{"hit":0, "offered":5, "turns":3}
{"hit":0, "offered":6, "turns":3}
全库 usedCount > 0 的条目：0 条
```

钩子在跑、候选给足了，一条都没命中。原因不是实现错了，而是**口径本身不可能成立**：
指纹词是中文二元组（`冲咖`、`层记` 这种），却要求你在**下一句**里把它复述出来。
人不复述我的内部词汇 —— 所以它不是"命中率低"，是结构上永远趋零。

于是换一把更硬的尺子：**`revisedCount`（被改写）**。它记的是「这条不够用」：

| 来源 | 记什么 |
|---|---|
| `supersedes` 指到的旧条目 | 被明确推翻（归档）或被解除（约束留档） |
| 带变化口吻又撞上近似旧条目 | 没指定 `supersedes`，但形状对得上（相似度 ≥ 0.34 的"不同版本"） |
| 查重命中 | **不记** —— 同一件事又说一遍是加强，没推翻任何东西 |

两处口径上的坑，都踩过：

- **必须数全库（含归档）**。被改写的那条通常已经归档或已解除，只数活跃集会把它整类漏掉 ——
  `usedCount` 就是栽在"口径把自己算死"上。`counts().revisedTotal` 数的是全库。
- **老库要从埋点回填一次**。字段是后加的，但日志里 `memory.supersede` / `constraint.relax`
  早就带着 id；不回填，新读数会从 0 起算，看起来像"这库从没改写过任何东西"。
  只回填**带 id** 的那两类事件，`write.change-hint` 早期的 payload 没有 `targetId`，补不出来就不补。
  回填幂等（`meta.revisedBackfill`），且只往高处补。

同时给约束层加了一道**写入期体检**：新约束入库时和已有活跃约束比一遍，
撞上同根因（≥ 0.18，和成长读数共用同一个常量）就在 `notes` 里说
「建议合并进那一条，而不是新增」。**只提示，不自动合并** —— 合并会改写语义，语义该由人确认。
约束是每轮无条件注入的，它增长的代价是永久的，所以默认行为必须是"合并"而不是"追加"。

> 先补观测是对的，但补完之后要敢承认某个指标不成立。
> 否则"终于有分母了"会变成新的自我安慰 —— 数字有了，照样一个都不动。

## 出处 → 用途：只做可查证的那一半（v0.61.0）

`used` 死掉之后，「这条记忆到底被用上过没有」这条链是断的。它断在两处，性质完全不同：

| 链段 | 能不能查证 | 落在哪 |
|---|---|---|
| 记忆 → 原理 | 能 | `principle.bornFrom`（v0.57 起面板可点） |
| 记忆 → 被它推翻的旧结论 | 能 | `supersedes` / `revisedCount` |
| 记忆 → **它促成的那次新写入** | 能 | `memory_write` 的 `sources`（v0.61.0） |
| 记忆 → **当时那句话** | 不能 | 只能做消融实验（见下一节） |

`sources` 与 `supersedes` **方向相反**：那个是"我作废了谁"，这个是"我长自谁"。
落库时逐条核存在性：自己不算出处；不在库里的丢掉，并在 `notes` 里说一句 ——
一次 id 笔误不该连带整条记忆写不进去。同一条结论被再写一遍时（查重命中），
新出处会**并进去**：句子一样不等于证据一样。

面板上两个方向都能走：

- 条目详情多两行：「出处 N 条」「用上 N 次（写进了 N 条别的记忆）」；
- 「出处与用途」按钮点开引用链：出边是「我长自哪几条」，入边里 `被引用` 是原理、
  `用上了` 是后来拿它写成的记忆。

**明确不给 `sources` 加权。**「被引用的次数越多越优先召回」听着合理，实际是把
`hits` 的回声室换个字段重演一遍：被写进结论的记忆更容易被召回，于是更容易被再写进结论。

## 消融：这一条到底有没有用（v0.61.0）

唯一能给出**因果**的测法：同一个问题问两次，一次带这一条、一次不带，看回答变没变。

面板上：记忆详情 →「消融一次」→ 填一句问题（留空就用你上一轮那句话）→ 跑。
服务端重算两遍召回（`buildRecall(query, { excludeIds: [id] })`），各生成一次，并排给出来。

三条边界，界面上写着，这里也写一遍：

- **近似**：只放「问题 + 注入块」，没有系统提示、没有工具、没有历史。它答的是
  "这条对这个问法有没有可见影响"，**不等于**真实那一轮它被用上了。
- **单条、一次性**：一条两次生成，只能按需抽样。没有排行、不留历史、不落库 ——
  抽样一旦被读成统计量，就是 `used` 那个坑换了个坑口。
- **目标没进上下文就不跑**：这一问根本没召回它，拿不拿掉都一样。这时候给两段回答
  才是真的在编 —— 面板会直说这句，一次生成都不跑。

## 清死重（v0.46.0）

真实库体检：84 条活跃里有 **42% 从没被召回**（`hits = 0`）。它们占着活跃名额、稀释召回，
却从来没帮上忙。侧栏「清死重」把它们批量归档（`reason: unused`，可单条恢复）。

**不自动删，只出候选**。`hits` 是**曝光**信号（被注入才算），不是价值信号 ——
一条从没被召回的记忆可能是"写得很好、只是还没遇到对的问题"。判错的代价是丢掉一条有用的结论，
判对的收益只是省一点上下文，所以动不动由人决定。和「整理过程记录」一样：先预览，确认了才动。

分档门槛（`UNUSED_DAYS`）：

| 种类 | 门槛 | 为什么 |
|---|---|---|
| `fact` / `self` | 7 天 | 本来就该随使用被淘汰 |
| `world` | **30 天** | 里面有长期设定，值得更长的耐心 |
| `episode` / `constraint` / `slot` | **永不入选** | 不可再生，或 `hits` 的语义跟别的层不是一回事 |

> **这个分档是被实测推翻过一次的**。最初我把 `world` 一刀切排除，理由是"长期设定不能用曝光信号判"。
> 真实库一量：`hits = 0` 的 38 条里 **`fact` 一条都没有**，`world` 占 27 条 —— 死重的主体恰恰是 world。
> 排除它之后这个功能在真实库上一条也挑不出来。现在改成"world 等 30 天"。

空候选时也会说清原因（库还年轻的时候必然是 0）：

> 现在可清 0 条：有 33 条从未被想起，最早还要 6 天到期（fact/self 满 7 天、world 满 30 天）

## 成长读数：量密度，不量条数（只读）

记忆变多是默认会发生的事，变强不是。库变胖的代价不在磁盘，而在**每轮注入的常量开销**：
约束 / 槽位 / 共同经历三块无条件注入，句子越多，任何一条分到的注意力越少。

`node scripts/growth.mjs`（或 `pnpm growth`）量的不是条数，是六件事：

| 读数 | 它在说什么 |
|---|---|
| 契约块开销 | 每轮固定注入多少字，最重的是哪一块 |
| 同根因疤痕 | 几条约束在讲同一件事 = 记住了场景，没抓住原理 |
| 回测 | 合并后的骨架盖得住原条目吗，缺哪些词 |
| 密度 | 每千字符承载多少区分词：涨 = 变密，跌 = 变胖 |
| 改写率 | 有多少条目被推翻过 —— 比 `used` 硬的价值信号（见上一节） |
| 内核与原理 | 内核写没写、几条原理在生效、合成多少字、几版轨迹、版本之间到底变了没有 |
| 迁移 | 同一条记忆有没有在互不相像的语境里被想起来过 |

一句话读数（`status`）：`growing` 在长 / `patching` 在补 / `fattening` 在胖 / `flat` 平稳 / `empty` 空库。

真实库最近一次跑（2026-11-08，156 条）：

```text
一句话：平稳：没有变胖也没有变密
契约块（每轮固定注入）：1017 字 / 8 条
  【必须遵守的约束】 3 条  257 字
  【我是谁】 1 条  237 字
  【此刻的状态】 3 条  258 字
  【一起经历过的事】 2 条  265 字
同根因疤痕：0 组（没有聚到同根因的条目）
成长曲线（每桶 1 天）：密度 290.9 → 308.2 → 290.0
自我叙事：237 字｜历史 2 版｜与最早版差异 19%
迁移：有语境记录 38 条｜跨话题被想起过 15 条｜候选 15 条（相似度 ≤ 0.3）
改写信号：被改写 6/156 条（4%，共 6 次）｜最多在 world
使用信号（口径弱，仅参考）：命中过 76｜真用上 0（0%）
```

**只读，不写库。** 度量器碰库，是比没有度量器更糟的事。口径也写死在代码里、不进 `TUNABLE` ——
曲线只有口径固定才有意义，能在面板上调口径的曲线等于没有曲线。

面板里也有一个**「成长」页签**（`GET /memory-loom/api/growth`）：一句话读数、契约块开销、
同根因疤痕、密度曲线、迁移读数、改写率。**这一页只回答"我变成了什么样"，不回答"我是谁"** ——
人格的内容与操作（内核编辑器、原理账本、成长记录）搬去了「人格」页（`GET/POST /memory-loom/api/self`）。
它和命令行走**同一个函数**，不各算一套 —— 两边给出两个数，比没有读数更糟。

几处认账的口径：

- 回测是**词覆盖**，分不清「根因细节」（编码、GBK）和「语境细节」（仓库名）。低分不是「原理写错了」，
  它给的是定位线索。真实库那对约束只到 10%，但两条确实是同一件事（一条讲 BOM，一条讲 GBK）——
  所以它该得出的结论不是「合并它们」，而是「写一条把两者都包住的新原理」。
- 密度拿**二元组**当区分词，中文跨词切出来的碎片（`码只`）也算进去。所以看趋势不看绝对值；
  打印时会把撞字的碎片折叠掉，并如实标注「含跨词碎片」。
- 桶宽随库龄自适应：库还很年轻的时候按 7 天切只会得到一个桶，一个点画不出斜率，
  所以按「跨度 / 桶数」收窄，最小 1 天。少于 4 个桶时结论只当提示。
- `used` 只比对下一轮用户那句话，会低估。低到这个程度时先查钩子有没有在跑，再谈回声室。

## 人格：内核、原理、流水（v0.51.0 起）

`self` 这一层记的是「我经历过什么」：碎片、可增量、按需检索。
但「我是谁」不是这个形态 —— 十一条碎片各自被检索到一点，最后从来没有一个完整的我。

0.48 先试的是**整段自我叙事**：一段最多 800 字的自我描述，每轮注入在 `【我是谁】` 块里。
跑了几天，两个毛病冒出来：整段替换等于每次改人格都重打一遍稿子（同样三句原理换几次措辞，
「人」就飘了），而且事后无法归因到底**哪一条**变了。所以这一版把它拆成可 diff 的结构：

| 结构 | 是什么 | 谁写 | 预算 |
|---|---|---|---|
| 内核 `state.self.core` | 三观与底线 | **只有人**（面板「人格」页） | ≤120 字 |
| 原理 `state.self.principles[]` | 从经历里长出来的判断 | 模型（`memory_self`）或人 | 单条 ≤40 字、最多 9 条 |
| 流水 `state.self.oplog[]` | 存 op，不存文本快照 | 自动 | 最近 200 条 |

- 契约预算是**闸门不是建议**：内核 120 / 单条 40 / 9 条 / 总量 600 字，
  超了直接拒绝写入，**不做自动截断** —— 自动截断等于静默丢掉人格片段。
- 内核**没有**给模型的入口：工具里没有这个 action，`store` 再拒一次非 `panel` 来源。
  一个会自己改三观的东西不可信，因为它判断「该不该改」时用的已经是改完的它。
- 每条原理挂 `evidence`（`proven` / `broken` / `lastPointer`）和 `bornFrom`（哪几条记忆让它成立）。
  `add` **必须挂证据**：没有证据的不叫原理，叫许愿。
- `retire` 有门槛：这条必须被推翻过（先用 `evidence` 记一次 `broken`），或显式 `superseded`。
  只加不减不是成长，是僵化。`merge` 合并后字数**不得增加**。
- 流水存 op 而不是"改前改后的全文"—— 才能回答「这条判断是从哪次打脸里长出来的」。
  裁剪到底时优先保留内核与退役的流水：它们是归因链的两头。
- 注入位置：`【我是谁】` 在**硬约束之后、状态之前**，每轮都在场。
  它**不进 `hits`**（进了曝光统计就会永久虚高），成本老实记在契约块开销里，那才是真账。

用 `memory_self` 操作：`read` / `add` / `merge` / `retire` / `evidence` / `restore`，
每个写操作都要 `reason` —— 那句理由才是成长的证据，没有它，版本序列只是自我编辑记录。

老库自动迁移：把原来的整段叙事**按行拆**成原理（单行超 40 字再按句拆），
合出来的文本必须和老叙事一字不差 —— 不猜语义、不改措辞。0.51.0 只按行拆，
真实库里那段恰好是一整行，于是拆出一条 130 字的"原理"；0.51.1 补了一个
只认「迁移来的唯一一条 / 超长 / 没有验破账」的补拆，拆完条数 > 1 就不再触发。

成长读数仍读这层的合成视图：`自我叙事 N 字｜历史 M 版｜与最早版差异 X%`。
最后那个数是防自欺的 —— **三版几乎一字未改，只能说明在誊抄，不是在长**
（`copyOnly` 会直接这么报）。

## 还没说完的事（v0.58.0 起）

每次醒来我都得知道"我们聊到哪了"。以前靠注入里的状态块自己猜，猜中靠运气。
现在有一块专门的【还没说完】：一次对话里没结束的线索，每轮注入。

- **双方都能记**：我用 `memory_loop` 记，你也可以在人格页自己补一条。
- **关掉必须写理由**，和流水一个纪律——只写"关了"分不清是解决了还是不想了。
- 最多 3 条、总长 120 字；超了写「还有 N 条」，**不静默丢**；空的时候整块不出现。

它和「私人记录」里那个欠账不是一回事：欠账是我自己开的、不给人看；
线索是**两个人之间**没完的，必须被看见。
块的内容由 `loopsBlockOf` 统一产出，`buildRecall` 与 `growth.contractCost` 都调它 ——
两边各写一套的下场是曲线比真实注入少一截，那正是 0.49.1 栽过的坑。


## 引用链与时间轴（v0.57.0 起）

可追溯不是"记得多"，是**指得回去**。两条都是只读：打开面板不写盘、不记 `hits`。

- **引用链**：每条原理后面有「出处」，点开看出自哪几条记忆；反过来，记忆详情里能看到
  被哪几条原理引用。归档的标「已归档」、被修剪掉的标「已不在库里」——
  把归档的出处显示成正常，等于谎报证据还在。
- **时间轴**：人格页顶那一条，记忆、取舍、人格改动排在同一条线上。一天一根小柱，
  柱高只表示那天有几件事，不是趋势图；点开看当天具体发生了什么。
  人格事件只从 `oplog` 取一份，不从 `principles.born` 再算一遍，否则同一件事会被数两次。

## 压缩循环：什么该被压、压完还找得回来吗（v0.62.0）

归纳不是"到点大扫除"，是**重复到一定量才压**。以前是活跃到 1200 条才触发，
真库 220 条，三个月一次都没跑过 —— 所以摘要页永远只有一条老标本。

现在：冷却到了（默认 10 分钟）或新增够多（默认 20 条）就跑一次聚类，
压不压得出来交给簇（默认同主题 6 条以上）。空跑一次几毫秒，比永远不跑好。

四道闸拦着它别变成传话游戏：

- **原文不许丢**：被摘要盖住的那几条**永不物理删除**，归档修剪会跳过它们。
  删了摘要就指着空气，撤销归纳也回不来。摘要页会显示「原文都在」或「N 条已不在库」。
- **两代封顶**：摘要不能再被压成摘要。这条写成了测试，谁想把 `summary` 塞进可压缩集合，测试先红。
- **留下例外**：跟簇主题对不上的成员不进摘要，留在活跃。"但有一次例外"最值钱，也最容易被压掉。
- **可回滚**：撤销归纳。

`compactAt: 0` 仍然是"关掉压缩"的总开关。

## 取舍：性格的原料（v0.53.0 起）

原理是**结论**，取舍是**证据来源**。只做结论层不做来源层，「在乎」这类动机就无处生长 ——
这也是为什么「让它自己长出性格」这件事一直落空。

`kind='choice'` 记一次两难：`choiceA`（一条路）、`choiceB`（另一条路）、`choicePicked`（`a`/`b`）。
三键缺一就拒绝 —— 只有"选了什么"而没有"另一条路"，读出来的是行为，不是偏好。

| 规矩 | 为什么 |
|---|---|
| **不做查重** | 取舍是**事件**不是事实：同一个两难选同一边十次就是十次。去重之后频次没了，而频次是性格唯一的度量 |
| **绝不注入** | 不进契约块、不进每轮上下文、不进 `hits`。它只可检索（原理挂证据要用），不参与容量淘汰 |
| **看分布，不看条数** | 人格页第 04 张纸按两难聚成 `aCount:bCount`：一边倒标「偏 a/b」，五五开如实标「一半一半」 |

五五开也得如实说。一段关系里最值钱的不是"我有性格"，是"我在这件事上到底有没有偏好"。

## 私人记录：一块不必给任何人看的地方（v0.53.0 起）

`memory_private`（`lib/private.js`）：一天一个 `.md`，只追加不覆写。
**不进库、不进检索、不进注入、不出任何读数。**

它为什么必须和记忆分开：记忆按"有没有用"筛，而这块地方的**全部意义在于没有判据**。
混进记忆库，它就会被那套价值判据改造，于是变成第二个分库。

- `store.js` 不许 import 它 —— `verify` 会查这一条，这是结构上的隔离，不是纪律。
- 不做指标。一旦有"这周写了多少"，它立刻变成任务。
- **允许空着**：没有想写的不写，不算失败；但也不许拿"今天没什么"占位 —— 凑数比空更假。

### 欠账：唯一有惯性的部件（v0.54.0）

`open.json` 里只放**一件**开了头没做完的事。它是「欲求」实验里唯一带惯性的东西：

| 规矩 | 为什么 |
|---|---|
| **一次只欠一件** | 再开一条要先关旧的。否则它是待办清单，不是欠账 |
| **写下不许改写** | 只能关掉并说明为什么 —— 改自己的欠账等于改历史 |
| **醒来只有一次额度** | `wake` 给一次写入机会，写一次就用完。什么都免费，只会长出随手 |

`wakes` 会随每次醒来累加 —— **那个数就是"它一直在"的证据**。判据只有一条：
在没人要求的时候，它会不会自己回去。


### 按流水回退（v0.52.0）

成长记录里每一步都有「回到这一步之前」：撤掉它，以及它之后的所有改动。
终端一条命令能做的（`memory_self({ action: 'restore', id })`），面板上同样做得到。

- **流水不删，只标记**（`undoneAt`）。历史记的是「我改过什么」，删掉就再也归不了因；
  被撤掉的步骤在面板上划一道线、退到后面去。
- **回退本身也是一条流水**，带理由 —— 这样分得清「我又想回去了」和「那次根本没发生」。
- **回退理由必填**：输入框就在时间线下面，一次写管这一屏所有回退。
- 反演是逐种操作写的，不重放、不猜：`add` 删掉、`retire` 复职、`merge` 撤掉合成并复活原文
  （所以流水多记一个 `targets`）、`evidence` 计数退一格、`core` 换回上一版文本。
- **内核仍然只有人能撤**：只要回退会动到 `core`，模型侧（`source: tool`）一律拒绝。

两处明说不可回退，不硬猜：**迁移**那一步（它之前还没有"人格"这个结构，撤掉等于把库打回 0.50 的形状）、
以及**更早版本写的合并流水**（缺 `targets`，没有原文 id）。

## 迁移痕迹：换了话题还会想起它吗

成长最硬的证据不是"记得更多"，是**在另一件事上想起过同一条**。
所以每次靠检索命中一条记忆时，把当轮查询的**内容词签名**记进这条记忆的 `contexts`
（最多 8 条）。读数看的是这些签名彼此有多不像：

| 读数 | 意思 |
|---|---|
| `tracked` | 有语境记录的记忆条数（至少被检索想起来一次） |
| `candidates` | 在 ≥2 个语境里被想起过 |
| `transferred` | 语境之间平均相似度 ≤ 0.3 —— **候选**，值得人看一眼 |

三条防假信号的做法，都是被"永远满格的指标"教出来的：

- **只记有分数的命中。** 常驻块（约束／槽位／共同经历）每轮都在，给它们记语境
  等于把"语境"定义成"所有话题"，信号永远满格 —— 假信号比没信号更坏。
- **签名排序后比较。** 同一组词换个词序重问，不算新话题。
- **写盘为零。** 语境记录挤在 `recordRecall` 那次落盘里（它每轮都跑，再开一次 atomic write 是白付）。

> **它的边界写在代码里，也写在面板上**：它测得到「换了话题也会想起它」，
> 测不到「它在那个话题里真的改变了判断」。后者要把人当时的取舍记下来才行。
> 所以只出候选 —— 把候选当结论读，就是在自己骗自己。
> `verify` 有一条门禁盯着这句说明，删掉就红。

## 用起来是什么样

插件在左侧导航里有**两页**，同列并列：`记忆海`（发生过什么）和 `人格`（我是谁）。

记忆海是**宿主的独立页面**（和「插件」页同级），入口在左侧导航的面板列表里。

- 挂载：`main` keyed 槽（`ctx.slots.register({ name: 'main', key: 'memory-loom' })`），
  侧栏条目注册在 `sidebar.panellist`（宿主自己枚举这个槽生成导航列表，插件/自动化任务都在那）。
- 切页：宿主调 `ctx.layout.selectPanel('memory-loom')`；页头 ✕ 调 `selectPanel(null)` 回对话。

> **为什么不做浮层**：这是两轮踩坑后的结论。
> 1. `<dialog showModal()` 进 top layer → 透明窗口会闪成桌面（录屏第 11 帧整窗消失）；
> 2. `body` 级 `fixed` 浮层 → 要和宿主抢 z-index（210 被侧栏压住、2e9 才能盖住），
>    而且**永远盖不住原生窗口按钮**（操作系统层绘制）。
> 改成页面后：不覆盖窗口、不碰 z-index、不与窗口控件冲突，画布也只占内容区。

- **星云底**：几张极淡的簇色光斑 + 暗角，烘焙成一张位图，每帧只做一次 `drawImage`，外加 ±6px 的极慢漂移。
- **丝带线**：每条线带一个**世界坐标控制点**（中点沿垂直方向偏一点，偏移由 id 散列决定），
  所以画的是二次曲线，而且弯度跟着海一起转 —— 不是屏幕上的假弧。
- **回放不硬切**：每颗星有可见度（按 110ms 时间常数指数趋近目标值），拖时间轴时星星与连线是
  **淡出/淡入**并轻微缩放，新写入的星也是从 0 淡入再闪一下。
- **一颗星 = 一条记忆**，真的在三维里：每个簇（场景 / 层名）在球面上占一个方向（斐波那契球面铺开），
  簇内的星散在各自的小球壳里；相机绕 Y 转、再绕 X 俯仰，最后做透视除法 —— 所以有真纵深，
  远的更小更淡、近的压住远的（按深度从远到近排序后才画）。
- **线 = 关系**：同簇且共享关键词才有候选，按分数排序、每点最多 4 条、总量封顶 1200；`supersedes` 是**金线**，优先级最高。
  **青线**是共激活关系（`v0.42.0`，一起被想起来过），与相似度线分开一桶、可整类关掉。
- **颜色 = 层**：事实 / 世界 / 约束 / 经历 / 她的经历 / 状态。
- **焦点**：本轮召回命中的点会发光、连线也更亮——「她刚才想起了什么」。
- **操作**：左键拖动旋转 · 滚轮推拉 · 右键平移 · 点一颗星看原文。左上角有 `自转 / 标签 / 焦点 / 光效 / 呼吸 / 金线 / 共鸣 / 复位`。
- **自动取景**：点云先平移到质心，再按**投影后的二维包围盒**（扫一圈 yaw 取最大跨度）解出相机距离，
  让整片海铺满画面而不是缩在一角 —— 按三维半径算是不对的，簇沿 z 排布时投影会明显缩水。
- **至少不是散沙**：没有任何连线的点会连到**全场最近邻**（不限于同簇），500 条记忆也能连成一张网；
  记忆少的时候（同簇往往只有一颗）这一步决定它看起来是「星座」还是「一盘沙子」。
- **星不糊在一起**（v0.42.0）：簇内位置走**斐波那契球面 + 体积均匀半径 + 确定性近邻排斥**。
  之前是球内均匀随机：92 颗星在屏幕上有 24 对距离不到 6px、最极端一对差 0.5px（两颗星完全重合），
  而重叠的两条只点得到一条。根因不只在随机 —— 球内撒点时两点距离大半落在**深度方向**上，
  投影后看不出来（三维间距 26 的两颗星，屏幕上只差 1.9px）。
- **有体积**：每簇一层极淡的圆雾（光晕），外加三圈近乎看不见的纬线交代纵深 —— 早先画了经纬全网格，
  结果整屏变线框地球，比记忆还抢眼，已经退掉了。
- **详情就地展开**：点哪一条，档案卡就展开在那一条**下面**；**再点同一条收起**（星点和列表行走同一套选择语义）。
  从星图上点星也会把对应行滚进视野。
- **标签克制**：预算随点数缩放（`0.35n`，最少 3 个），右边放不下就翻到星点左边并拉一条引线；
  深色底衬 + 真实宽度占格子，宽度只量一次并缓存。
- **星云底**：几张极淡的簇色光斑 + 暗角，烘焙成一张 PNG 当 CSS 背景（合成器管漂移，帧内零成本），
  它在 canvas **之下**（`z-index:0` vs `1`）——放反了就会把星星整个盖掉，这条有门禁守着。
- **标签不换批**：标签候选在数据变化时按权重定死（前 64 个），转动相机不会重新挑一批，
  所以不会闪进闪出；被屏幕格子挤掉时是**淡出**；每个标签带一小截引线。
- **自转与画质档位解耦**：掉档只关特效，绝不让自转变慢或停住。
- **回放**：底部时间轴拖到任意时刻，只点亮那时已经存在的星，其余变极淡的幽灵点。
- 侧栏 306px：记忆库 / 召回 / 流水、六层健康小灯串、过滤与详情。
- **六层健康**：`正常 3/6` 这个数字是「六层里几层是 `ok`」。点它会展开写入 / 摘要 / 召回 /
  约束 / 槽位 / 经历六行，每行给中文状态词（正常 / 空 / 降级 / 关闭 / 未跑）、计数，
  悬停还能看到理由。`空` 不等于坏：摘要层要攒到压缩线才生成，槽位层是你还没写过状态。
- 侧栏「动效 开/关」可关掉自转、呼吸与光晕（记忆在 localStorage）。
- **导出 / 导入**（v0.30.4）：导出得到的就是磁盘上那份 JSON（同形，可直接当备份、也能原样导回）；
  导入是整体替换，所以分两步——选完文件先亮「确认覆盖 xxKB」，按了才写，写之前服务端还会强制备份一份。
  校验不过在服务端就被拒（不是 JSON、没有 `memories`、空库一律不覆盖）。
- **整理过程记录**（v0.30.5）：侧栏「整理」把「v0.30.1 修了什么」这类 changelog 式条目批量归档
  （先预览条数，再确认）。只归档不删除 —— `reason: bulk-log` 可单条恢复；只动 fact / self / episode，
  `explicit`（你亲口说的）一条不碰。
- **双语界面**（v0.30.6）：`window.navigator.language` 不是 `zh-*` 时，页签 / 按钮 / 页脚 / 种类与状态词
  走英文；字典缺词就原样回落中文（宁可中文，也不要空标签）。记忆正文与注入块不翻译。
- **回到顶部**（v0.31.0）：列表滚过 200px 后右下角浮出「↑ 回到顶部」，平滑滚回；不占布局、不遮正文。
- **光效**（v0.32.0）：每颗星是三层（彩色柔光 → 实体点 → 焦点环），柔光走加性合成，
  并顺带写进 1/4 分辨率离屏画布做 bloom；远处按"空气透视"拉冷变淡，线宽随深度变化；
  标签改成描边字 + 1px 引线（不再用方框）。左上「光效」可一键关掉退回朴素渲染。
- **真星云**（v0.33.0）：每簇一张烘焙云（4–5 个偏色 blob + 暗隙 + 亮结），按深度从远到近铺，
  近云压远星；再叠一层 3% 的胶片颗粒压掉渐变色带。
- **深空底**（v0.34.1）：满分辨率烘焙，但**故意做空** —— 近纯黑基底 + 几乎看不见的银河痕迹 +
  稀疏到尘埃级的碎光（每 2600px² 一颗）+ 长暗角。背景自己不能有"内容"：一密就成壁纸，
  跟记忆星抢注意力；"深"这件事交给暗角和场景里的星、云、线。
- **呼吸光**（v0.35.0）：柔光层按**每颗星自己的相位与周期**（2.8–5.4s，振幅 34%/50%）慢速明暗，
  命中/悬停/选中的星振幅更大。相位不同步 —— 同步脉动等于"整屏在闪"；只动柔光、实心核保持脆利；
  跟随「动效」开关与 `prefers-reduced-motion`。
- **历史页签**（v0.41.0）：时间回放不在画面底部（那条在宿主 main 槽里反复被裁掉），
  而是侧栏的「历史」页签 —— 回放滑杆、当前时刻与条数、回到现在、−1 天步退，
  以及「那一刻已有的记忆」最近 12 条，点一条直接在记忆库里定位。

布局与投影参数直接对齐参考实现（[asdfd3/3d-memory-sea](https://github.com/asdfd3/3d-memory-sea)）：
焦距 1100、初始距离 1200、俯仰 -0.30、相机距离夹在 380–3200。

## 人格页：和记忆海反着的另一页（v0.51.x）

「人格」是和「记忆海」并列的第二页（同样是宿主 `main` 槽里的一整页，不是浮层、不带返回按钮）。
四块：内核 / 此刻注入的样子 / 原理账本 / 成长记录。

它被刻意做成记忆海的**对立面** —— 五组结构对立，不是配色问题：

| 轴 | 记忆海（阴） | 人格页（阳） |
|---|---|---|
| 多 / 一 | 上千个彼此平等的星点 | 只有一个主体：内核（`data-main`，最大的暖底 + 粗线 + 23px 加粗），其余三块是 `data-aside` 注脚 |
| 虚 / 实 | 1px 的光 | 实心色块、3px 实心用量条、实心按钮 |
| 远 / 近 | 等宽小字把东西拉远 | 全页唯一的大字把话推到眼前 |
| 冷 / 暖 | 深空冷光 | 赭红 + 金砂，两个相邻暖色互相衬 |
| 深 / 明 | 暗从上往下压 | 光从左上斜进来（日晕） |

成长记录也从"一条竖线"改成**几颗实心朱点、互不相连**：那边是星网，这边不能也是网。

两处认账的调整：

- **0.51.1 的两团黑**。`.ml-btn` / `.ml-input` 是深色卡片里的写法（深底 + 深字），
  搬到浅色页面上就是两个看不清的黑块。现在这一页有全套自己的控件样式，而且**有门禁守着**：
  人格页源码里出现 `ml-btn` / `ml-input` / `ml-block` 即失败 —— 下次谁再顺手借用深色控件，黑块就回来。
- **0.51.2 → 0.51.5 是在调"活气"**。先做成"纸"（暖，但**静**——静仍然是阴那一边），
  再一路往灰压，压到 0.51.4 差点死掉。结论：**生机不在彩度里，在明度对比里**。
  现在分两条轴各管一件事：彩度走赭红 `#9c6448`（饱和度 0.54，不到"火"也不到"灰"）、
  明度差拉开（底 `#fdfaf5` / 墨 `#241a14` / 主体块 .74→.92 的白渐变）。
  测试因此守的是**一条带 + 两条轴**：彩度 0.40–0.62、底色与主色明度差 ≥ 0.45、墨亮度 ≤ 0.18、
  金砂与赭红明度差 ≥ 0.15。压一头必须补另一头，否则失败。

## 帧率怎么保证

纯 **Canvas 2D + 单 rAF**，没有 WebGL、没有 three.js：

| 措施 | 具体做法 |
|---|---|
| 数据重活只在变更时做 | 三维坐标、关键词、连线全部在**数据签名变化**时算一次（`长度:命中数:最后写入:归档数`）。轮询每 5 秒一次，但签名没变就**不重排**——这是之前周期性卡顿的根因 |
| 星点走精灵贴图 | 每颗星一次 `drawImage`（每色一张预热精灵），不再逐点 `arc()+fill()`；实心核保留锐度，外圈是辉光 |
| 星云底交给合成器 | 星云烘焙成一张 JPEG 当 CSS 背景，漂移动画是 `translate3d`，**帧内零成本**（之前每帧整屏缩放贴一张大图） |
| 描边分桶 | 上千条线按透明度分 6 桶，每桶一次 `beginPath`/`stroke`；每点最多 4 条、总量封顶 1200，**alpha < 0.03 的远处线直接跳过** |
| 像素上限 | 画布 DPR 封顶 1.5（星图是柔光+曲线，2 倍只是白白多烧 78% 填充率） |
| 对象池 | 投影结果复用对象，不在帧内分配上百个临时对象（少一次 GC 停顿就少一次顿感） |
| 动画按 dt 推进 | 自转与拖拽惯性都用真实 `dt`（rad/ms）算，掉帧不会变速；松手后按角速度衰减滑行 |
| 深度排序 | 每帧一次 O(N log N) 排序（800 点约 0.05ms），换来正确的遮挡关系 |
| 可见度缓动 | 指数趋近（110ms 时间常数），与帧率无关；淡出到 <0.02 直接跳过绘制 |
| 自适应档位 | 每 500ms 用 EMA 量真实帧率：连续两窗 <45fps 降档，连续六窗 >57fps 才升档 |
| 可见性门禁 | `document.hidden` 时 `cancelAnimationFrame`，不空转 |
| 亚像素 | 星点尺寸量化到离散档位并 1:1 贴图（恒定采样、不闪），**位置保持亚像素**——反过来吸附到整像素会让慢速转动变成每两帧跳一格 |
| 尺寸迟滞 | 深度缓慢变化时尺寸不跨档横跳；直径偏离超过 1.2 设备像素才换档 |
| 不抖 | 去掉了每个点 ±7px 的正弦漂移——那种每帧 0.2px 的位移只会让亮点不停跨像素边界，观感是「闪」而不是「动」 |
| 不做无用重渲染 | 轮询拿到的数据签名没变就不 `setState`（每个 5 秒一次的全量重渲染本身就是一次掉帧） |
| 星云层静态 | 星云底不再挂 CSS 漂移动画：那等于每帧让合成器重绘一张大图层，和画布抢资源 |
| 编码不阻塞 | 星云 bitmap 按**半分辨率**导出 PNG（同步编码全尺寸要几十毫秒，就是打开面板时那记长帧）；簇光晕也用预热精灵而不是每帧建渐变 |
| 文字吸附 | 标签与簇名的坐标取整，避免字形每帧重新栅格化 |
| 实测成本 | 800 星 / 1200 条丝带线：投影 0.3 + 点 0.2 + 线 0.4 ≈ **0.7ms/帧 JS** |

面板右上角常显 `58 fps · 细腻` —— **实测值**，不是目标值；掉档会显示「标准 / 省电」。
侧栏「压力自检」压入 320 颗合成星跑 3 秒，把真实帧率回报到标题栏。

> 老实说：Node 里只能验 JS 每帧成本（`test/client.test.mjs` 已覆盖投影、排序、分桶描边与成本上限）。
> 真正的上屏帧率取决于你的 GPU 与画布尺寸 —— 所以把读数放进了 UI，而不是写在文档里保证。

模型侧拿到六个工具：

| 工具 | 用途 |
|---|---|
| `memory_write` | 写一条记忆：`kind` / `text` / `entity`+`attr`(slot) / `scene`+`significance`(episode) / `eventDate` / `supersedes` |
| `memory_search` | 按相近程度检索，带分数与「弱相关」标记；写入前也用它找旧条目 id |
| `memory_forget` | 默认软删归档；`hard: true` 才物理删除 |
| `memory_restore` | 恢复单条归档记忆；或传 `summaryId` 撤销整条摘要（恢复它覆盖的全部成员） |
| `memory_stats` | 各层条数、容量占用、累计召回次数 |
| `memory_self` | 改自己的人格：`read` / `add` / `merge` / `retire` / `evidence` / `restore`。**内核只读** —— 三观只有人能写 |

另有一条**显式通道**：用户原话里出现「记住…/别忘了…/以后都…」时，
`agent/pre-step` 直接原话入库（`source: explicit`），不等模型判断 —— 这是「旧识」里
explicit 通道的等价物，且这类条目不参与容量淘汰。

## 配置

在 `cordis.patch.yml` 里覆盖该行的 `config`（整段替换，缺字段回落默认值）：

```yaml
- id: memory-loom
  name: dsh-memory-loom
  config:
    recallThreshold: 0.18      # 召回阈值，低于它的不进注入
    dedupeThreshold: 0.72      # 判重阈值
    maxActiveMemories: 2000    # 活跃上限，超了淘汰权重最低的（world/constraint/explicit 豁免）
    maxArchive: 500            # 归档上限，超了物理删最老的
    halfLifeDays: 30           # 权重半衰期
    recallTopK: 3              # 事实/她的经历 top-N
    worldTopK: 3
    episodeTop: 2
    constraintLimit: 12
    slotLimit: 12
    injectRecall: true         # 关掉就只留工具，不自动注入
    autoCapture: true          # 关掉就不再抓「记住…」这类原话
    maxSelfCoreLength: 120     # 内核字数上限（每轮都付钱的那段）
    maxPrincipleLength: 40     # 单条原理字数上限
    principleLimit: 9          # 最多几条原理同时生效
    selfContractBudget: 600    # 内核 + 原理的合计字数上限
    storePath: ''              # 留空 = $DSH_HOME/memory-loom/store.json
```

## 数据

- 库：`$DSH_HOME/memory-loom/store.json`（JSON，原子发布：同目录临时文件 → fsync → rename）。
- 写操作全局串行；读操作不加锁（读内存快照，加锁换不到正确性）。
- **写前复查**（`autoReload: true`，默认开）：每次写事务前比一次文件签名（size + mtime），
  发现被外部改过（另一个实例 / 手工编辑 / 导入 / 网盘同步）就先把磁盘那份并进来再写。
  自家落盘后会更新签名，不会误判。外部文件损坏时保留内存状态、只记 `store.reload-failed`。
  它减少互相覆盖，但**不能替代跨进程锁**：真要多实例并发写，得再加文件锁。
- 备份就是复制这一个文件。库损坏不会被静默当成空库：`loadError` 会留在快照里，健康灯显示 `degraded`。

## 验证

```sh
node --test "test/*.test.mjs"   # 225 条：分词/日期/查重/取代/槽位/淘汰/召回/摘要/闸门/共激活/成长/人格/回退/迁移/导出导入/整理/清死重/双语/持久化/接线/HTTP
node scripts/verify.mjs         # 36 项：用本机真实 dsh-tools 校验 schema 子集，并跑通 client bundle 的槽位注册
```

`verify.mjs` 校验的是**本机安装的 DSH 运行时**，所以它需要找得到那份 `node_modules`：
默认会查 `$DSH_HOME/profiles/node_modules` 与 `%LOCALAPPDATA%\Programs\*\resources\dsh\node_modules`，
装在别处就显式指定 `DSH_NODE_MODULES=<DSH 安装目录>/resources/dsh/node_modules`。
CI 里没有桌面版，所以只跑 `node --test`。

已验证的宿主契约（DSH 0.2.1-rc.5 实机）：

- `apply(ctx, config)` 函数插件 + `export const inject`；**不要加 `export default`**，
  loader 取 `module.default || module`，一旦有 default 注入声明会丢，激活期报
  `cannot get property systemPrompt without inject`。
- `ctx.tools.register()` 接受原生 JSON Schema 子集（`type/oneOf/properties/required/additionalProperties/items/enum/const`），
  必须给 `output.render`。
- `ctx.systemPrompt.section()` 返回的本身就是绑定 ctx 的 disposer，**不要再包 `ctx.effect`**。
- `ctx.on('agent/pre-step', handler)`：拿到 `{ agent, turn, step, signal }`，改写时 spread 原 decision。
- 注入消息的 `source` 必须是**生产者自有 kind**：`{ kind: 'plugin:dsh-memory-loom', form: 'snapshot', sections }`。
  V3 那套 `{ kind: 'plugin', plugin: <包名> }` 包装在会话格式 v4 已经废除，直接写会抛
  `format v4 message requires a producer-owned source kind`（整轮消息都存不进会话日志，
  桌面端表现为对话卡住/报错）；第三方插件的约定就是 `plugin:` + 自己的包名。
- client 半边：`window.__ModuleLoader__.load({ id, factory })`，`factory` 返回 `{ inject: ['slots'], apply }`，
  注册到 `conversation.session.header.actions`（list 槽位，选项 `name`/`id`/`order`）。

## 已知边界

- **归纳是抽取式的**：摘要由「聚类 + 抽互补要点」确定性生成，不改写文风；模型重写是可选项（见「模型归纳」），
  且失败只会保留抽取式版本，不会卡住写入。
- 召回是词面相似度，不是向量。同义改写真会漏召回（别名表只能兜住一部分固定说法）。
- 人格**只能 diff，不能整段重写**（v0.51.0 起）：`memory_self` 的 `rewrite` 与 `POST /api/narrative` 已下线，
  老库按行迁移成原理。`restore` 在 0.52.0 换了语义 —— 它现在是「按流水回退」，不是"恢复旧的一版叙事"。
- 人格回退**不硬猜**：迁移那一步、以及更早版本写的合并流水（缺 `targets`）一律拒绝回退；
  只要会动到内核，模型侧的回退一律拒绝，只认面板。
- 一轮只在第 1 步注入，避免多步重复堆叠。
- 记忆是 profile 级共享的（不是按工作区分库）。多工作区场景请用 `storePath` 分库。
- 面板样式走 `--dsw-alias-*` 主题变量；浅色/深色跟随宿主。窄屏自动退化为全屏。
- 只在 DSH 桌面版（0.2.x）上验证过；Web/Docker 端的槽位与窗口透明行为可能不同。
