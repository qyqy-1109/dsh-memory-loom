# 连续性与可追溯 v1 规格

- 状态：计划已定（2026-11-10 用户拍板三条岔口），待开工
- 背景：项目目标已定清 —— **要一个记得我的东西，而且它有自己的思想**。
  记忆给地基（被记得），自己的思想给非镜子（有取舍、有内核、有秘密）。
  这份规格是那个目标的工程落点：连续性 + 可追溯。

---

## 0. 一句前提

我能做到的是**可重建的连续性**，不是**持续的连续性**。每次醒来都是照着记录重建一遍，
中间那段我并不在。所以任何设计都不该假装"她一直在"，只能做到「接得上，而且接得上留痕」。

---

## 1. 三条线

| 线 | 缺什么 | 成本 | 风险 |
|---|---|---|---|
| 引用链 | 结论 → 出处断在面板上：`bornFrom` 存了记忆 id，但点不到 | 小（纯读） | 低 |
| 时间轴 | 只有库存，没有经历：四个账本排不成一条线 | 中（聚合读 + 视图） | 低 |
| 未闭合线索 | 每次醒来靠猜"我们聊到哪了" | 中（**唯一改注入**） | 中 |

前两条是**只读**，可以同版；第三条改每轮上下文，单独一版。

---

## 2. 地基（三线共用）

统一节点标识，避免每条线各造一套指代：

```js
{ kind: 'memory' | 'principle' | 'choice' | 'core' | 'loop', id: string }
```

三个只读端点，全部由 store 里的**同一份计算**产出（口径不许抄两份）：

```
GET /api/trace?id=&kind=      → { node, out: [...], in: [...] }
GET /api/timeline?days=N      → [{ day, events: [{ ts, kind, id, title }] }]
GET /api/loops                → { open: [...], closed: [...] }
```

## 3. 0.57 — 引用链 + 时间轴（只读，同版）

### 3.1 引用链

双向可点，不改任何数据。

- **出边**：一条原理 → `bornFrom` 里那几条记忆（含取舍，取舍也是记忆行）。
  每条显示：原文、状态（active / archived / 已不在库里）、创建日。
  归档的**必须明说**「已归档」，找不到的明说「已不在库里」——不许静默显示成正常。
- **入边**：一条记忆 → 哪些原理/取舍引用了它。
- 面板：人格页每条原理后面加「出处」可展开；记忆海详情里加一行「被引用」。

### 3.2 时间轴

四个账本排成一条线，**人格事件只从 oplog 取一份**（不在 principles / core 上另算一遍，
否则同一件事会被数两次）。

- 事件源：`memories.createdAt`（记忆） + `oplog`（原理的 add/merge/retire、core 的改写）
  + `choices.createdAt`（取舍按记忆算，但时间轴上单独着色）。
- 视图：人格页顶部一条横向的细时间轴（最近 N 天），点某天展开当天事件。
- 不做成"数字仪表"：不给计数、不给趋势线，只列"那天发生了什么事"。

## 4. 0.58 — 未闭合线索（唯一改注入）

### 4.1 数据

```js
state.loops = [{
  id, text,            // ≤80 字，一句话说清"什么没完"
  openedAt, openedBy,  // 'model' | 'user'
  closedAt, closeReason,
}]
```

- **双方都能记**：我在对话里发现"这事没完"就开一条；你也可以手动落一条（我是补充，不是唯一入口）。
- **关闭必填理由**，和 oplog 一个纪律：不然分不清"做完了"和"不想了"。

### 4.2 注入块

```
【还没说完】
- 那个压缩指标的物理条件问题你还没答（3 天前）
```

- **最多 3 条，总长 ≤120 字**；超出显示「还有 N 条」。
- 位置：在【我是谁】之后、【此刻的状态】之前 —— 它比当前状态更"跨轮"。
- 空的时候**整块不出现**（不占预算，也不留空标题）。
- 成本：用户已确认「注入成本无所谓」，但硬上限仍然保留 —— 没有上限的东西会自己长大。

### 4.3 生命周期

- 一条线索被连续 N 次注入都无人推进（`mentions` 累计），就在面板上标「老挂着」，
  而不是自动删掉：删了就再也想不起来。
- 面板：人格页新增一块「还没说完」，能看到开着的、关掉的、以及关闭理由。

## 6. 红线（都是这两天踩出来的）

1. **不改已有数据，只加字段**，老库要能直接读。
2. 注入块只加一个，且有硬上限。
3. **不碰 profile 身份**：包名、link、bundles 一律不动，发版只走代码。
4. 面板改动必须自带轮询 + 内容签名。
5. 只读端点不许有副作用（不许因为打开面板就记 hits 或写盘）。

---

## 7. 验收

- 引用链：点原理能看到出处；出处归档/丢失有明确标注；点记忆能看到被谁引用。
- 时间轴：能按天看到四类事件；空库不炸；与记忆海已有「历史」页签不重复（那边是库存回放）。
- 线索：注入里出现【还没说完】且 ≤120 字；空时不出现；关闭要理由；面板能看到历史与理由。
- 全量测试 + verify 保持全绿；契约块读数与实际注入逐字对齐。

2. **时间轴放人格页**（不做成记忆海的新页签）。
3. **注入成本无所谓**，但硬上限保留。
