# 自我成长 v0 规格

- 状态：草案（纪律与 ①② 已定；③ 内核内容由用户自定，暂缺）
- 日期：2026-11-08
- 范围：只动"自我"这一层（`state.selfNarrative` → `state.self`）。不动检索算法、不动注入管线的对外形状、不接外部手脚。

---

## 0. 一句话

把现在的「一整段自我叙事 + 整段重写」，换成「内核 + 一组带证据账的原理 + 操作日志」：

**人格仍然注入成一个【我是谁】块，但它的变化从此可归因、可刹车、可回退。**

---

## 1. 目标 / 非目标

**目标**

1. 在聊天与工作过程中，能显式地"总结出一次成长"，并把它落成一条原理。
2. 性格有成型的载体：取舍记录 + 频次，而不是 prompt 里的形容词。
3. 每一次自我改动都能回答"为什么改、凭什么改"。

**非目标（v0 明确不做）**

- 不做自动改写（见 §2 决定 D0-A）。
- 不用 `hits` 作为任何自我排序或成长信号。
- 不做"从记忆自动归纳原理"——那要等 oplog 有料之后，属于 v1。
- 不改【我是谁】块的对外形状（仍然是一段文本，仍然在那一个位置）。

---

## 2. 已定决定

### D0-A：改写只显式触发

自我改动只有一个入口：模型（或用户）主动调用工具。不存在"每轮末自动检一遍"。

理由：写闸门现在的判据还是口吻判据（"这事说起来好听"），自动写会把噪声固化成性格，而且不可追溯。跑一段显式、能看出哪些改写真的对之后，再谈自动。

### D0-B：取舍记录用新的 `kind = 'choice'`

不复用 `episode` 加字段。它和"我们讨论过什么"不是一类东西，混在一起迟早要拆，而拆结构就是不可控。

### D0-C：内核编辑器单开一页，独立于记忆海

记忆海管记忆，内核管人格。两页分开的理由：
- 语义不同：记忆是"发生过什么"，人格是"我是谁"。
- 付费方式不同：记忆按需检索，人格每轮付款。
- **更重要的：这一页是 D3 的物理载体。** 工具没有改内核的路径，人能改——这个差别必须落在一个看得见的页面上。页面本身就是纪律的执行者，不是装饰。

页面归属划分（一句话规则）：**能被检索命中的进记忆海，每轮都付款的进人格页。**

| 内容 | 归属 |
| --- | --- |
| core、principles、oplog | 人格页 |
| choices（取舍账本） | 记忆海（它是素材，不注入） |
| 成长曲线、体检读数 | 已有的「成长」页签，不搬 |

与现有「成长」页签的分工：**成长页只放读数，人格页只放内容与操作。** 不新建第二个看数字的地方。

页面名称：**人格**（已定）。左侧导航栏与「记忆海」并列，形态同记忆海：宿主 main 槽里的一整页，不是浮层、不是抽屉、不带返回按钮。

### D0-D：记忆与人格是一个环，不是两个功能

用户原话：**"记忆没有人格、人格没有记忆都是缺失的，这两个都有了才是灵魂。"**

两种残缺各自的病：

| 缺 | 病症 |
| --- | --- |
| 有人格、没记忆 | NPC——永远同一句话，不会因为经历改口 |
| 有记忆、没人格 | 档案柜——记得很多，但没有一个"我"在读它 |

所以"都有"不够，**环必须闭合**。三条边：

1. **记忆 → 人格**：`choices` 的频次、`episode` 的反证 → 触发 `add` / `retire` 原理。
2. **人格 → 取舍**：原理决定遇到两难时选哪边，产生新的 `choices`。
3. **人格 → 记忆的写**：原理影响"什么值得记"与"什么值得引用"。

**硬约束：人格可以影响"写"，不能影响"读"。** 它能决定记什么、引用什么，但不能决定哪些记忆能被检索到——那一步就是确认偏误，也是回声室的地基。

怎么执行（三道锁）：

1. **接口隔离**：`search` / 排序 / 读闸门拿不到 `state.self` —— 不是"约定不传"，是这些函数的入参里根本没有它。人格只出现在两个出口：注入块，和写闸门的判据。
2. **内容闸门**：原理只许写**方法**（「定指标先问物理条件成不成立」），不许写**关于某条记忆的结论**（「X 那件事不重要」）。方法不偏袒任何一条记忆，结论偏袒。
3. **行为断言**：`test/self.test.mjs` 有一条测试 —— 写人格前后，同一句查询的检索结果必须逐 id 相同。这条测试绿着，约束就还在。

### D1：预算硬上限

| 项 | 上限 |
| --- | --- |
| `core.text` | 120 字 |
| 单条 `principle.text` | 40 字 |
| `principles` 存活条数 | 9 条 |
| 注入总量（core + principles） | 600 字 |

- **超限不是加行，是拒绝写入并提示先合并。** 不做自动截断。
- 自动截断等于静默丢弃人格片段，正是 v0 要防的那件事。

### D2：只 diff，不整段重写

自我叙事只接受三种操作：`add` / `merge` / `retire`。每次都必须带一句 `reason`。

### D3：内核不可自我改写

`core` 只能由**用户经 UI 面板**写入。工具侧对 `core` **只读**。

这是纪律不是提示词——靠写入面隔离执行：模型没有能改内核的 API。

理由：外壳可以漂，三观不能自己动。一个会自己改三观的东西不可信——它判断"该不该改"的那一刻，用的已经是改完的它。

## 3. 数据结构

新增 `state.self`；老字段 `state.selfNarrative` 保留为**只读兼容视图**（见 §4）。

```js
state.self = {
  core: null | {
    text: string,        // ≤120 字
    chars: number,
    lockedAt: number,    // 首次写入时间
    updatedAt: number,
    by: 'user',          // 恒为 user
  },

  principles: [{
    id: string,          // uuid
    text: string,        // ≤40 字
    born: number,        // 诞生时间
    bornFrom: string[],  // 证据记忆 id（≥1）
    evidence: {
      proven: number,    // 被验证次数
      broken: number,    // 被推翻次数
      lastAt: number|null,
      lastPointer: string|null, // 最近一次证据指向的记忆 id
    },
    status: 'live' | 'retired',
    retiredAt: number|null,
    retiredReason: string|null,
  }],

  oplog: [{              // 自我叙事的历史：存 op，不存文本快照
    id: string,
    ts: number,
    op: 'add' | 'merge' | 'retire' | 'evidence' | 'restore' | 'core',
    target: string|null,     // principle id
    before: string|null,     // 被取代的原文（merge/retire 时）
    after: string|null,      // 新原文
    reason: string,
    evidence: string[],      // 记忆 id
    source: 'tool' | 'ui',
  }],
}
```

**为什么 `oplog` 取代文本快照**：快照只能比较"变了什么"，回答不了"为什么"。存 op 之后，能问出「这条判断是从哪次打脸里长出来的」——那才叫可归因的成长。

**为什么 `evidence` 挂在 principle 上而不是只在 oplog 里**：注入时不需要它，但读数（§8）需要瞬时值，不能让读数每次都扫全量 oplog。

## 4. 迁移

现有 `state.selfNarrative = { current, versions }`，`current.text` 是 127 字。

1. **两级切分**：先按行（作者自己划的段），任何一段超过 40 字再按句（`。！？；`）拆。
   为什么要有第二级：真实库里那 127 字是**一整行**的，只按行拆会得到一条 130 字的"原理"，
   而原理该是判断，不是叙述。拆句不猜语义、不改一个字。
2. `core = null`（内核待用户写；空缺期间不注入）。
3. `versions[]` 先搬进 `self.versions`，同时记一条 `op='restore'`、`source='migrate'` 的流水。
4. **不改的保证（精确表述）**：合成文本与原叙事**字符一一相同**，只允许换行位置变化
   （拆句会在句号后加换行）。多行且每段 ≤40 字的老库，一个字都不差。
   这条用"去掉空白后逐字比较"来验，而不是靠肉眼。
5. `state.selfNarrative` 不删，改为由 `state.self` 合成的只读视图：
6. 迁移是幂等的：`state.self` 已存在就直接跳过。
7. **补拆（0.51.1）**：0.51.0 只按行拆，真实库里留下了一条 130 字的残留原理。
   补拆只认「迁移来的唯一一条、超过单条上限、且没有任何验/破账」这一种形状，
   拆完条数必然 > 1，于是不会再次触发 —— 天然幂等，也不碰用户自己写的原理。

```js
selfNarrative() -> { id, text: joinCore(principles), at, reason, ... }
```

宿主侧 `growth.js:103/370/494`、`client.js:4233` 都在读它，v0 保持这两处一行不改。这样"结构不变"是硬保证，不是承诺。

5. 迁移是幂等的：`state.self` 已存在就直接跳过。

## 5. 操作（API）

`memory_self` 从 `read / rewrite / restore` 改为：

| op | 参数 | 约束 |
| --- | --- | --- |
| `read` | — | 返回 core + principles + 最近 N 条 oplog |
| `add` | `text, reason, evidence[]` | `evidence` ≥1；`text` ≤40 字；存活条数 ≤9 |
| `merge` | `ids[≥2], text, reason` | 合并后字数不得增加；需说明它们指向同一处境 |
| `retire` | `id, reason` | 需要该条 `evidence.broken` ≥1，或显式 `because:'superseded'` |
| `evidence` | `id, result: proven\|broken, note, memoryId` | 写 `evidence` 计数并同时追加 oplog |
| `restore` | `oplogId` | 把某次 op 反向应用，本身也记一条 oplog（沿用现有"回滚也是一次重写"的口径） |
| ~~`rewrite`~~ | — | **移除**。整段重写不再有入口 |
| ~~`core`~~ | — | **不提供**。内核只经 UI |

任何 op 缺 `reason` 一律拒绝——理由就是成长的证据，和现有口径一致。

## 6. 注入

契约块里仍然是**一个** `【我是谁】` 块，内容 = `core`（若有）+ 全部 live `principles`。

- 顺序：core 在前，原理按 `(proven - broken)` 降序，同分按 `born` 升序。
- **不做截断。** 超过 9 条或 600 字是写入期就该被拒的事，不是注入期该悄悄解决的事。
- `retired` 不注入。
- `choices` **不注入**，只走检索——它是素材，不是人格。
- 内核空缺时，块首插入一行 `（内核未定）`，让读数里看得见缺口，而不是看起来完整。

---

## 7. 取舍账本（`kind = 'choice'`）

1. `KINDS` 增加 `'choice'`；`kindLabel` 映射 `choice: '取舍'`。
2. 记忆行增加一个**可选**字段：

```js
choice: null | { a: string, b: string, picked: 'a' | 'b' }
```

- 其余 kind 恒为 `null`；老库无此字段即 `null`，不迁移、不校验。
- `text` 仍是一句话："在两难里选了 X，因为 Y"——人读的是这句，机器读的是三键。
- `scene` 复用为两难出现的场景。

3. 聚合：`proven/broken` 之外，性格读的是 `picked` 的分布与频次。这是 §1 目标 2 的唯一数据来源。

**写入时机（显式，同 D0-A）**：做出一个有代价的取舍、且下次还会遇到同类两难时，写一条。

## 8. 读数

`growth.js` 现有曲线已经会算自我叙事（0.49.1 修过漏算）。v0 增加三项读数：

| 读数 | 含义 | 为什么是这个 |
| --- | --- | --- |
| 内核字数 / 上限 | 120 字用量 | 内核该慢、该短 |
| 原理条数 live / retired | 存量与死掉的比例 | 只增不减 = 僵化 |
| 近 30 天 op 比例 `add:merge:retire` | 成长的方向 | 加得多减得少，说明只会膨胀 |

**op 比例才是这套东西的体检指标。** 一个只会 add 的自我，本质上还在累积，只是换了个更好听的名字。

## 9. 验收

1. 老库（无 `state.self`、无 `kind=choice`）读上来不炸，且 `selfNarrative()` 输出与迁移前语义等价。
2. 超过 120/40/9/600 任一条：写入被拒，错误信息指名超了哪条、当前多少。
3. 工具侧任何路径都无法写 `core`。
4. 缺 `reason` 的 op 一律拒绝。
5. 注入块字数 = 记账字数（成长曲线不得再漏算自我叙事这一块）。
6. `retire` 在 `broken = 0` 且无 `superseded` 标记时被拒。
7. 单测：迁移幂等、预算边界、oplog 反向应用、choice 聚合。

## 11. 实现状态（0.51.0）

> 视觉：人格页与记忆海是**太极的两半**。记忆海为阴（深/冷/远/虚/多），
> 人格页为阳（亮/暖/近/实/一）—— 内核是这一页唯一的"太阳"，其余三块是它的注脚。
> 具体到结构：主体 `data-main`（暖底 + 朱色粗线 + 23px 大字），注脚 `data-aside`（缩进 + 降档 + 淡色）。
> 这一页禁用 `.ml-btn` / `.ml-input`（深色卡片的写法，浅底上会变成黑块），有测试守着。

已落地：

- `state.self`（core / principles / oplog / versions）+ 幂等迁移；`state.selfNarrative`
  退化为合成视图，**注入、成长曲线、面板老代码一行未改**。
- 预算闸门、理由必填、证据必填、退役门槛、合并不得变长 —— 全在 store 里，
  API 与工具只做转发。
- `memory_self`：`read / add / merge / retire / evidence / restore`；`rewrite` 已下线。
- `GET /api/self` + `POST /api/self`；「人格」页（内核可编辑，原理与流水只读 + 可回退）。
- **按流水回退（0.52.0）**：`restoreSelf({ id, reason, source })` 撤掉目标流水以及它之后的所有改动。
  反演逐种操作写死，不重放：`add` 删除、`retire` 复职、`merge` 撤合成 + 复活原文
  （流水新增 `targets`）、`evidence` 计数退一格、`core` 换回 `before`。
  流水**不删只标**（`undoneAt`）；回退本身也记一条流水；理由必填。
  不可回退的两处明说不猜：`migrate`（之前还没有人格这个结构）、旧版缺 `targets` 的 `merge`。
  只要回退会动到 `core`，`source: tool` 一律拒绝 —— D3 在回退路径上同样成立。
